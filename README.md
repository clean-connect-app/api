# Clean Connect API

Сервер клиентского оформления, личного кабинета и бронирования интервалов. Расчёт корзины и проверка контактов перенесены из прототипа [`p1`](https://github.com/danilbiriukov/Engineering-Thinking/tree/3308cd37863a231579c6929c560050e93d314b70/students/%D0%91%D0%B8%D1%80%D1%8E%D0%BA%D0%BE%D0%B2%D0%94%D0%98/p1).

## Локальный запуск

Понадобятся Node.js 24 (точная версия в `.nvmrc`), npm и PostgreSQL. Для чистой базы можно использовать Docker Compose.

```powershell
Copy-Item .env.example .env
docker compose up -d --wait
npm ci
npm run migrate
npm run seed
npm run dev
```

Если PostgreSQL уже запущен, укажите строку подключения к пустой базе в `DATABASE_URL` и пропустите команду Docker. Команда `seed` создаёт две демонстрационные химчистки. У обеих общий тестовый прайс, отдельная ёмкость интервалов и срок обработки в один календарный день. Для работы с реальными данными задайте отдельные настройки, включая `APP_ORIGIN` с HTTPS.

API слушает `127.0.0.1:3000`. Проверка доступности находится на `/api/health`. Клиентский веб по умолчанию открывается на `http://127.0.0.1:5173` и направляет запросы `/api` на сервер. При размещении за обратным прокси сохраняйте исходный `Host`.

## Вход по email

Настройте веб-приложение у провайдера OpenID Connect с входом по одноразовому коду на email. Для Auth0 подходит Passwordless Email с Universal Login. Зарегистрируйте адрес возврата `http://127.0.0.1:5173/api/auth/callback` и метод обмена кода `client_secret_basic`. Провайдер должен отдавать подтверждённый email в ID token. Укажите `OIDC_ISSUER`, `OIDC_CLIENT_ID` и `OIDC_CLIENT_SECRET` в локальном `.env`. Для Auth0 с отдельным подключением Passwordless Email укажите также `OIDC_CONNECTION=email`. [Документация Auth0](https://auth0.com/features/passwordless)

Параметры входа и сессии хранятся в PostgreSQL. Вход доступен после заполнения параметров OIDC, а каталог и расчёт цены можно проверить сразу после запуска.

## Проверки

`npm run check` запускает линтер, проверку форматирования и типов, тесты и сборку. Для проверки HTTP и конкурентных броней задайте `TEST_DATABASE_URL` с доступом к отдельной тестовой базе. Тест создаёт временную схему и удаляет её после прогона.

Маршруты описаны в [OpenAPI](openapi.yaml). Для редактирования сервер проверяет статус, версию и ожидаемую сумму. При смене интервала прежняя бронь освобождается только после успешной записи всей правки.
